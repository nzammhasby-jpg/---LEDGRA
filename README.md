# LEDGRA | لِدجرا للمحاسبة السحابية (المرحلة الثانية - الهيكل المحاسبي والسنوات المالية) 🚀

منصة محاسبية وسحابية متطورة لإدارة المنشآت والأعمال، تمثل المرحلة الثانية لتأسيس البنية التحتية والمنظومة المحمية الأساسية للمنصة وبناء الهيكل والدليل المحاسبي الذكي. يشتمل هذا النظام على عزل كلي للمستأجرين المتعددين (Multi-Tenant Isolation)، وإدارة قوية ومنيعة للسنوات والفترات المالية المتطابقة مع متطلبات وضوابط الأنظمة المحاسبية السعودية، وإدارة ذكية لدليل الحسابات (Chart of Accounts) مع توجيه ترحيل أمين عبر الإعدادات المحاسبية الافتراضية للمنشأة.

---

## ✨ ميزات وإضافات المرحلة الثانية الحالية (Phase 2 Current Features)

1. **السنوات والفترات المالية (Fiscal Years & Periods)**
   * **تأسيس معالج دوري آلي**: بناء وتفتيت السنة المالية المختارة ديناميكياً إلى فترات شهرية مسلسلة ومغلقة بمسارات مخصصة.
   * **الحماية من إشارات التعديل**: تجميد وتأمين إخترابات التعديل والصيانة للفترات للحفاظ على سلامة الحركات؛ الميزات والمسارات مهيأة للعزل وإدارة الإغلاق المالي.
   * **أرقام لاتينية موحدة**: إعمال التواريخ والأرقام اللاتينية الإنجليزية في جميع الواجهات لضمان سلامة التكامل مع محركات التقرير.

2. **دليل الحسابات الهيكلي (Chart of Accounts Tree)**
   * **دليل شجري هرمي**: عرض شجري مرن، ديناميكي، وقابل للتمدد لعرض مستويات الحسابات المحاسبية الخمسة (الأصول، الالتزامات، حقوق الملكية، الإيرادات، المصروفات).
   * **إدارة وتأسيس وحذف ذكي**: إضافة وتعديل الحسابات مع حظر فوري وبقوانين صارمة لتفادي مرجعيات الحسابات الدائرية (Circular References) أو التعديات على حسابات النظام الافتراضية.
   * **اختيار الأب وتوليد الرموز المحمي**: تحديد الحساب الأب ديناميكياً مع فرض مطابقة الرمز (Sub-code starts with parent code) والتحقق من توافق نوع الحساب وطبيعته الحسابية (classification/nature).

3. **الإعدادات والتوجيهات المحاسبية (Accounting Settings)**
   * **خرائط الحسابات الافتراضية**: تخصيص حسابات الترحيل النهائية للصندوق والبنك والعملاء والموردين وضرائب القيمة المضافة ومبيعات السلع والخدمات وتكلفة المبيعات ومجموع الأرباح المدورة.
   * **منيعة الحذف للمحددات الافتراضية**: حظر قطعي بروتوكولي لقاعدة البيانات يمنع حذف أي حساب جاري استخدامه في خرائط الإعدادات الافتراضية حماية للربط الدفتري من التلف.

## 🛠️ التقنيات المستخدمة في المشروع

*   **الواجهة الأمامية:** React + Vite
*   **لغة البرمجة:** TypeScript لضمان موثوقية الأنواع وتفادي الأخطاء البرمجية.
*   **التنسيق والتصميم:** Tailwind CSS الموحد والمبسط لضمان واجهة سريعة الاستجابة ومتناسقة الألوان والهوية.
*   **المصادقة وقاعدة البيانات:** Supabase PostgreSQL & Supabase Auth.
*   **إدارة البيانات والاتصال:** TanStack Query (React Query) لإدارة الذاكرة المؤقتة لبيانات المستأجرين.
*   **التأثيرات الحركية:** Motion لضمان تجربة مستخدم سلسة ومرنة.

## 📂 هيكلة وتأمين قاعدة بيانات Supabase

يمكنك تهيئة وتحديث قاعدة البيانات وفق حالتين متميزتين لضمان حماية البيانات المتواجدة ومنع الكتابة العشوائية فوقها:

### الحالة الأولى: عند البدء بمشروع Supabase جديد وفارغ كلياً (New/Empty Project Setup)
1. قم بإنشاء مشروع جديد في منصة [Supabase](https://supabase.com).
2. من القائمة الجانبية اختر **SQL Editor** ثم اضغط على **New Query**.
3. انسخ كامل المحتويات من ملف الهيكل الموحد `supabase/initial_schema.sql` (والذي يجهّز البنية الأساسية والمستخدمين والمنشآت).
4. الصق المحتويات في المحرر واضغط **Run**.
5. بعد نجاح حركة التجهيز الأساسي، افتح **New Query** جديدة وانسخ محتويات ملف التحديث المحاسبي المكمل `supabase/migrations/20260617000000_phase2_accounting.sql` وقم بلصقه وتشغيله لتجهيز جداول المرحلة الثانية المحسنة (`fiscal_years`, `fiscal_periods`, `accounts`, `accounting_settings`) مع تفعيل كافة دوال الصلاحيات والأمان المتين.

### الحالة الثانية: عند الترقية وتطبيق التحديثات على مشروع قائم وعامل مسبقاً (Existing Project Upgrade)
* ⚠️ **تحذير**: لا تقم مطلقاً بتشغيل ملف `supabase/initial_schema.sql` على مشروع قائم، لتفادي الكتابة فوق جداول المنشآت والمستخدمين المتواجدين وخسارة البيانات!
1. اذهب مباشرة إلى **SQL Editor** داخل مشروعك القائم في منصة Supabase.
2. اضغط على **New Query**.
3. انسخ فقط محتويات ملف الترقية للمرحلة الثانية: `supabase/migrations/20260617000000_phase2_accounting.sql`.
4. الصق الكود واضغط **Run** لتطبيق جداول السنوات المحاسبية وإدارة الحسابات وربط الإعدادات الآمن وقواعد الصلاحيات المكملة دون المساس ببيانات المستخدمين التاريخية.

### 🔒 الخصائص الأمنية المطبقة في الهيكل:
* يفعّل قواعد الحماية الصارمة **RLS (Row Level Security)** لعزل بيانات كل منشأة عن المستخدمين الآخرين تماماً.
* يدمج `SET search_path = public, pg_temp` في دوال الـ `SECURITY DEFINER` كتدبير أمني متقدم يمنع ثغرات الاختراق وحقن المسار.
* جميع الدوال آمنة وتستخدم `auth.uid()` داخلياً دون السماح للعميل بتمرير معرف مستخدم آخر.

## 🔒 إعداد بيئات Supabase منفصلة (Dev vs. Production Setup)

كأفضل ممارسة هندسية في الأنظمة المالية الحساسة، يتوجب عزل بيئات التطوير والتحقق الفني كلياً عن بيئة الإنتاج والتشغيل الفعلية لتفادي تسرب بيانات العملاء أو الاختلاط السري للحسابات:

### ١. إعداد مشروع Supabase للتطوير (Development Project)
* قم بإنشاء مشروع مخصص في Supabase يسمى `LEDGRA-DEV`.
* نفذ فيه ملفات الـ SQL بالمسارات: `supabase/initial_schema.sql` أولاً ثم `supabase/migrations/...`.
* استخدم المتغيرات التالية في ملف التكوين المحلي الخاص بالتطوير `.env.development`:
  ```env
  VITE_SUPABASE_URL="https://dev-project-id.supabase.co"
  VITE_SUPABASE_ANON_KEY="dev-anon-public-jwt"
  ```
* قم بربط مسار الإرجاع (Redirect URL) ببيئة الاستضافة المحلية: `http://localhost:3000/#/reset-password`.

### ٢. إعداد مشروع Supabase الفعلي والإنتاجي (Production Project)
* قم بإنشاء مشروع منفصل ومستقل تماماً يسمى `LEDGRA-PROD` يضمن العزل الكلي وتراجع الصلاحيات.
* فعّل فيه تدابير الخصوصية والنسخ الاحتياطي اليومي، ونفّذ هيكل سكريبتات قاعدة البيانات الموحدة ذات الصلة.
* استخدم المتغيرات التالية في بيئة الإنتاج `.env.production` أو إعدادات لوحة التحكم السحابية لمضيف المشروع (مثل Cloud Run / Vercel):
  ```env
  VITE_SUPABASE_URL="https://prod-project-id.supabase.co"
  VITE_SUPABASE_ANON_KEY="prod-anon-public-jwt"
  ```
* اربط مسار الإرجاع (Redirect URL) بناموس النطاق الفعلي للمشروع: `https://app.ledgra.com/#/reset-password`.

## 🔑 متغيرات البيئة الأساسية (Environment Variables)

يتطلب التطبيق توفير متغيرات البيئة التالية للعمل بشكل صحيح داخل ملف الـ `.env`:

```env
# رابط الاتصال بمشروعك على Supabase
VITE_SUPABASE_URL="https://your-project-id.supabase.co"

# المفتاح العام لـ Supabase (Anon Key)
VITE_SUPABASE_ANON_KEY="your-anon-public-jwt-key"
```

*(ملاحظة: تم إلغاء الاعتماد على متغير البيئة `VITE_APP_URL` حيث يقوم التطبيق بتحديد أصل الرابط تلقائياً باستخدام المتصفح لتبسيط التشغيل دون أخطاء أو تعليق).*

### ⚠️ هام جداً: تفعيل رابط استعادة كلمة المرور (Redirect URL)
لضمان نجاح حركة استعادة وإعادة تعيين كلمة المرور بأمان تام، يجب تسجيل رابط إعادة كلمة المرور كأحد الروابط الموثوقة للتوجيه التلقائي في حسابك على Supabase:
1. اذهب إلى لوحة تحكم **Supabase** لمشروعك.
2. من القائمة الجانبية اختر **Authentication** ثم اذهب إلى قسم **URL Configuration** -> **Redirect URLs**.
3. قم بإضافة رابط التطبيق متبوعاً بمسار استعادة كلمة المرور، على سبيل المثال:
   - في بيئة التطوير المحلية: `http://localhost:3000/#/reset-password`
   - في بيئة النشر الفعلية: `https://your-domain.com/#/reset-password`
4. اضغط على **Save** لحفظ التغييرات بنجاح.

## 💻 طريقة تشغيل وتطوير المشروع محلياً

لتشغيل خادم التطوير محلياً واختبار المنصة:

```bash
# ١. تثبيت الحزم والمكتبات المعتمدة
npm install

# ٢. تشغيل خادم التطوير (على المنفذ 3000)
npm run dev

# ٣. بناء نسخة الإنتاج الجاهزة للنشر والتحقق التام من البناء
npm run build

# ٤. فحص سلامة وتوافق أكواد الـ TypeScript والـ Linting
npm run lint
```
