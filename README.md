# LEDGRA | لِدجرا للمحاسبة السحابية 📊💼

لِدجرا هي منصة محاسبية وسحابية متطورة مصممة خصيصاً للمنشآت والمؤسسات، تضمن أعلى مستويات الدقة والأمان في إدارة العمليات المالية والقيود المحاسبية وإثبات الهوية البصرية والمخرجات المكتوبة طبقاً لقوانين التجارة والأنظمة المحاسبية المتفق عليها.

تمثل المرحلة الحادية عشرة **مرحلة التدقيق الأمني الشامل، وتطهير وهيكلة الكود، وفحص الصلاحيات، واستقرار الأنظمة وتجهيز نسخة الإطلاق المتكاملة**.

---

## ⚡ الابتكار والمميزات في المرحلة 11 (Audit, Security & Code Stabilization)

*   **تطهير وضبط الإجراءات السريعة (HashRouter compatibility)**: 
    *   إنهاء استخدام المقاربات اليدوية غير الآمنة والقديمة مثل `window.location.search` و `window.history.replaceState`.
    *   توحيد آليات التشغيل لصفحات الإنشاء السريع (Invoices, Customers, Payments, Items) بشكل كامل عبر React Router `useLocation` و `useNavigate`.
    *   التوافق التام مع نظام الـ `HashRouter` لضمان فتح النوافذ المنبثقة التلقائية مباشرة وتطهير رابط التوجيه بدون تكرار أو وميض.
*   **تدقيق الأمن وسلامة البيانات الهيكلية (Row-Level Security & Remote Procedure Calls)**:
    *   تأكيد تفعيل سياسات الحماية على جدار قاعدة البيانات **RLS (Row Level Security)** لعزل بيانات جميع الكيانات التجارية.
    *   فحص جميع دوال الـ `SECURITY DEFINER` والتأكيد على احتوائها للمحدد الأمني `SET search_path = public, pg_temp` وإزالة الامتيازات العامة `REVOKE ALL ON FUNCTION ... FROM PUBLIC` وحصر الوصول للمصادقين `authenticated`.
    *   توثيق وحماية مخزن شعارات المنشأة `organization-assets` كوعاء مغلق وخاص، حيث تفرز الملفات بالمعرف الفريد وكل عمليات الإضافة والحذف والتعديل محصورة فقط بـ `owner` و `admin` للمنظمة.
*   **سلسلة الترخيص وصلاحيات الدخول (Role-Based Access Control)**:
    *   رسم وتأكيد شبكة الصلاحيات والأدوار الهرمية الخمسة من الواجهات الأمامية والتحكمات الخلفية.
*   **استقرار واعتمادات التشغيل**:
    *   توليد وتحديث وحقن ملف `package-lock.json` في جذر المشروع لضمان إعادة توليد البيئة بشكل مطابق في بيئات التشغيل والإنتاج باستخدام `npm ci`.
    *   التأكد من التوافق التام مع البناء والتدقيق وخلو الأكواد من الأخطاء والتحذيرات.

## 👥 شبكة الصلاحيات والأدوار المحسنة (Role-Based Access Matrix)

تم إعداد ومطابقة الصلاحيات داخل واجهة لِدجرا وربطها بالتحقق البرمجي الآمن عبر الأدوار المحاسبية التالية:

| الدور (Role) | الصلاحيات المحاسبية والعملياتية | القيود على مستوى لوحة التحكم وقاعدة البيانات |
| :--- | :--- | :--- |
| **Owner (المالك)** | صلاحية كاملة ومطلقة على بيانات المنشأة، رفع الشعار، تغيير التوجيه، إغلاق الفترات، وإجراء المعاملات والمستندات. | غير خاضع لأي قيود مبيعات، يرى تكلفة المخزون ومتوسط WAC والعملاء والموردين. |
| **Admin (المدير)** | يرى ويعدل كل شيء مثل المالك تقريباً، ويدير الهوية التجارية ويرفع شعار المنظمة وملاحظات الطباعة القانونية. | صلاحيات كاملة على المشتريات والمبيعات والتقارير المالية والتحكم الإداري بالمنظمة. |
| **Accountant (المحاسب)** | إدارة الفواتير، السندات، الحركات المحاسبية، المخازن، والاطلاع الشامل على ميزان المراجعة والتقارير المالية. | **ممنوع** من تعديل الهوية البصرية القانونية للمنظمة أو تغيير بيانات السجل التجاري والاسم التجاري للمنشأة. |
| **Sales (المبيعات)** | يرى ما يخص المبيعات، ومصادقة مسودات العملاء، وتحرير الفواتير المباشرة. | **محظور كلياً** من الإطلاع على التقارير المالية (قائمة الدخل، المركز المالي) والقيود اليومية والتحكم في إعداد العمليات؛ كما يتم إخفاء أسعار WAC وتكلفة المخزون الإجمالية عنه حفاظاً على الخصوصية. |
| **Viewer (المشاهد)** | قراءة فقط لجميع المستندات والتقارير المحددة له لمتابعة سلامة السير. | **محظور كلياً** من أي عملية إضافة، تعديل، قيد، أو مسح لجميع الكيانات في المنظمة. |

## 🔒 حماية وتعيين المخزن السحابي (Company Logo Storage Policy)

تتبع المنصة بروتوكولاً عالي الأمان لحفظ وإدارة شعارات المنشأة:
1.  **bucket مخصص وسري**: ينشأ bucket سري باسم `organization-assets` وتكون صفة الوصول الافتراضية له `public = false`.
2.  **أمن المجلد والمعرف (Organization Folder Isolation)**: يُرفع الشعار في مجلد يحمل معرف المنشأة الفريد `organization_id`.
3.  **تفتيت سياسات الوصول (RLS)**:
    *   **القراءة (SELECT)**: مسموحة فقط للمستخدمين المصادقين الذين لديهم عضوية فعالة في نفس الجدول وبشكل يطابق اسم المجلد، عبر تصفية `storage.foldername(name)[1]`.
    *   **الإدارة (INSERT/UPDATE/DELETE)**: محصورة كلياً بالملاك والمدراء الفعليين للمنشأة لمنع الاستبدال العشوائي من قبل بقية الأدوار.

## 🛠️ التقنيات الهندسية المستخدمة (Tech Stack)

*   **الواجهة الأمامية**: React + Vite + TypeScript.
*   **التصميم والتناسق**: Tailwind CSS المدمج والموحد لضمان سرعة التحميل ومطابقة تذييل الأسطر والمكونات بنمط عصري.
*   **الحركات والمؤثرات**: Motion لضمان انتقالات انسيابية غير متشنجة للواجهات والموديلات.
*   **محرك البيانات السحابي**: Supabase PostgreSQL & Auth & Custom Security Definers.
*   **حفظ وإدارة الجلسات**: سياق React (Context API) لإدارة حالة العضوية والمنشأة النشطة بالتكامل الآمن مع Supabase Client.

## 🔑 متغيرات البيئة الأساسية (Environment Variables)

يتطلب تشغيل التطبيق محلياً أو في الخادم توفير المفاتيح الخاصة بالربط مع تكنولوجيا Supabase داخل ملف `.env`:

```env
# رابط قاعدة بيانات Supabase الخاصة بالمشروع
VITE_SUPABASE_URL="https://your-project-id.supabase.co"

# المفتاح العام للمشروع (Anon Key)
VITE_SUPABASE_ANON_KEY="your-anon-public-jwt"
```

*(تنويه: لا يتم استخدام VITE_APP_URL لضمان مرونة فائقة وتلقائية في قراءة خادم الأصل).*

4.  **قاعدة العملاء، الموردين ودليل الأصناف والخدمات (Phase 4)**: `20260619000000_phase4_master_data.sql`.
5.  **دورة المبيعات وسندات القبض وحوسبة السداد (Phase 5)**: `20260620000000_phase5_sales_invoices_receipts.sql`.
6.  **دورة المشتريات وسندات الصرف والخصم النزيه (Phase 6)**: `20260621000000_phase6_purchase_bills_payments.sql`.
7.  **سلامة المخاطر والمتوسط المرجح وحقن COGS (Phase 7)**: `20260622000000_phase7_basic_inventory.sql`.

9.  **طباعة كشوفات وتحليلات مخصصة (Phase 9)**: طباعة A4 للفواتير والسندات والكشوف والتقارير من المتصفح مباشرة بدون PDF Server وبدون ZATCA/QR/XML.

11. **مرحلة التأسيس لـ ZATCA (Phase 12)**: جدول e_invoice_artifacts وإدخال أساسيات الفوترة الإلكترونية وعرض رمز QR.

## 🚫 ميزات وقدرات خارج نطاق البناء الحالي (Not Built/Excluded)

لتفادي تشتيت النظام ومطابقة متطلبات العقد والجدول الزمني بدقة، **لا تشتمل النسخة الحالية** على تفعيل التالي:
*   التحقق والربط الإلكتروني المباشر الفوري بفوترة هيئة الزكاة والجمارك والضريبة (ZATCA Integration Phase 2 API).
*   نظام الرموز الثنائية المشفر للطباعة الفاتورية (Base64 Cryptographic QR) أو إرسال المعاملات الفورية للمطابقة والتخليص المباشر (Clearance & Reporting).
*   تخليص المعاملات والتقارير عبر ملقمات XML الفوقية.
*   تكامل أدوات ZATCA SDK داخل المتصفح أو الخادم مباشرة (عملية الفحص تتم خارجيًا ويدويًا عبر الأداة الرسمية للهيئة، ويسجل المستخدم النتيجة يدويًا للتوثيق والامتثال).
*   خوادم PDF خارجية (توليد الطباعة يتم محلياً بالكامل ومزامنتها في المتصفح).
*   خطط الدفع والفوترة واشتراكات الـ Stripe.
*   الذكاء الاصطناعي والمحركات التوجيهية للأنشطة.
